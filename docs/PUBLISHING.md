# Repository publication

Before publishing a release or a new repository:

1. Run `npm ci`, `npm run build`, `npm run typecheck`, `npm test`, and
   `npm run check:publication`.
2. Inspect the actual Git file list and commit history. Include source,
   migrations, public documentation, and the lockfile. Exclude credentials,
   local translations, storage, exports, screenshots containing real data,
   build output, and generated archives.
3. Confirm fresh-install instructions require the new owner to create their
   own administrator, products, channels, knowledge, and provider settings.
4. Create the intended GitHub repository and push only this reviewed Git history.
5. Check the first CI run. Enable private vulnerability reporting, repository
   security alerts, and suitable branch protection/rules for `main`.
6. Require pull-request review and successful CI before accepting contributions.

The repository uses the MIT license. Dependency licenses continue to apply.
Do not upload runtime data or a backup of a working installation as a release.
The optional SDK source ZIP is generated by `npm run package:android-sdk`;
inspect its contents before distributing it.

GitHub's server-side settings are configured after the repository exists; the
files in this project do not enable them automatically.
